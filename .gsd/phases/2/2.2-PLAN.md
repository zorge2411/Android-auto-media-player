# Plan 2.2: Remote Source Error Handling

## Objective
Provide robust visual feedback if a video playback fails (e.g., due to network drops, transcoder failure, or unavailable media). The app currently traps the player in an `Error` state with a black screen; it should actively alert the user and return to safety.

## Context
- .gsd/SPEC.md
- app/src/main/java/com/pscholer/autoplayer/car/screens/VideoPlaybackScreen.kt
- app/src/main/java/com/pscholer/autoplayer/player/MediaPlayerManager.kt

## Tasks

<task type="auto">
  <name>handle-playback-errors</name>
  <files>
    - app/src/main/java/com/pscholer/autoplayer/car/screens/VideoPlaybackScreen.kt
  </files>
  <action>
    - Add a new `lifecycleScope.launch` in the init block to collect `playerManager.playbackState` flows.
    - If the state changes to `MediaPlayerManager.PlaybackState.Error`, do the following:
      1. Trigger a `CarToast.makeText` with `LONG` duration displaying the error message.
      2. Call `playerManager.stop()` to reset the player pipeline.
      3. Call `screenManager.pop()` to abandon the screen.
  </action>
  <verify>grep -q 'PlaybackState.Error' app/src/main/java/com/pscholer/autoplayer/car/screens/VideoPlaybackScreen.kt</verify>
  <done>User is notified via toast when a video cannot be played.</done>
</task>

## Success Criteria
- [ ] Attempting to play an invalid video gracefully returns the user to the previous menu with a Toast alert.
- [ ] Network errors yield feedback instead of silent black screens.
