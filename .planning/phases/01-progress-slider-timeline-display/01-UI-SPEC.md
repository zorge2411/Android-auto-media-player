# Phase 1 — UI Design Contract: Progress Slider & Timeline Display

> Visual and interaction contract for Phase 1. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Platform Context (Critical)

This phase operates on **Android Auto via Car App Library**, not standard Android Views and not any web framework. All UI components must be expressed as Car App Library model objects. There is no SeekBar or Slider widget available in any Car App Library template type. The design contract below reflects the constraints of the **NavigationTemplate** (the only template type that provides SurfaceContainer access for video rendering).

| Constraint | Detail |
|-----------|--------|
| Template type | NavigationTemplate |
| Interactive control slots | ActionStrip (right edge, max 4 actions), MapActionStrip (top-right, max 4 actions) |
| Text display slot | NavigationTemplate.setNavigationInfo(MessageInfo) |
| Drag/scrub input | Not available — Car App Library has no Slider/SeekBar in any template |
| Driver distraction | Car App Library Restriction API enforces parked-only interactivity automatically |
| Seek resolution | Step-seek via ActionStrip buttons only (10-second increments) |

## Typography

Typography within Car App Library templates is controlled by the host and is not configurable by the app. The following contract governs the **timeline string** content rendered inside `MessageInfo` — the only text surface Phase 1 writes to.

| Role | Format | Example | Source |
|------|--------|---------|--------|
| Timeline position | HH:MM:SS | 00:42:17 | TimeFormatter.formatMillis() — already implemented |
| Timeline separator | " / " (space-slash-space) | — | buildTimelineText() in VideoPlaybackScreen |
| Timeline full string | HH:MM:SS / HH:MM:SS | 00:42:17 / 01:23:45 | Requirement: FEAT-1-AC4 |
| Zero/unknown state | 00:00:00 / 00:00:00 | — | TimeFormatter returns "00:00:00" for ms <= 0 |

No font size or weight is configurable — the Car App Library host renders MessageInfo text at its own system-defined size.

## Interaction Contract

This section replaces the standard "Copywriting Contract" for Android Auto phases, which have no standard form fields or CTAs. Phase 1 interactions are purely control-strip actions.

### ActionStrip Layout (Right Edge)

Slot order is fixed — Car App Library renders ActionStrip buttons top-to-bottom in add order.

| Slot | Icon | Action | Behavior |
|------|------|--------|----------|
| 1 | ic_seek_back | Seek back 10 seconds | playerManager.seekBack() — already implemented |
| 2 | ic_play / ic_pause | Toggle play/pause | playerManager.togglePlayPause(), icon swaps on isPlaying state change, invalidate() triggers re-render |
| 3 | ic_seek_forward | Seek forward 10 seconds | playerManager.seekForward() — already implemented |

### MapActionStrip Layout (Top-Right)

| Slot | Icon | Action | Behavior |
|------|------|--------|----------|
| 1 | ic_favorite / ic_favorite_filled | Toggle favorite | favoriteRepository.add/remove, isFavorite state toggles icon |
| 2 | ic_pause | Stop and exit | playerManager.stop() + screenManager.pop() |

Note: The stop button currently uses ic_pause. CLAUDE.md TODO captures switching this to a more appropriate stop icon (e.g., ic_stop or ic_close). This is a polish task outside Phase 1 core scope but the icon swap is a one-line change to MapActionStrip slot 2.

### Auto-Hide / Reveal Behavior (User Decision — LOCKED)

Controls (ActionStrip, MapActionStrip) and timeline text (MessageInfo) **disappear after a period of inactivity and reappear on tap**. This is a first-class interaction requirement, not a polish item.

| Property | Value | Notes |
|----------|-------|-------|
| Auto-hide timeout | 3 seconds | After last user interaction or initial playback start |
| Trigger to reveal | Tap anywhere on the video surface | SurfaceCallback touch event (MotionEvent.ACTION_UP on the SurfaceContainer) |
| Hidden state | NavigationTemplate rendered with `setNavigationInfo(null)` + no ActionStrip + no MapActionStrip | Or equivalent empty-strip approach — exact API to be confirmed in PLAN |
| Visible state | Full template with ActionStrip + MapActionStrip + MessageInfo timeline | Normal render path |
| Reveal duration before re-hiding | Resets the 3-second timer on each tap | Tapping again while visible restarts the countdown |
| Playback state change | Show controls immediately on play/pause toggle; restart 3-second timer | Ensures the user sees confirmation of state change |
| Real-time position update | Timeline text updates at 1Hz during playback while controls are visible | No update needed while hidden (controls not shown) |

**Implementation approach (to be verified in PLAN):** A `Handler` / `coroutine delay` on the main thread posts a hide action 3 seconds after the last interaction. Touch events on the SurfaceContainer (via `SurfaceCallback.onSurfaceTouched` or `Session.onCarConfigurationChanged` — exact API TBD in research) trigger reveal + timer reset. The `invalidate()` cycle already exists; hide/show is achieved by toggling whether ActionStrip/MessageInfo are included in the built template.

### Timeline Display (NavigationTemplate.setNavigationInfo)

| State | Display | Notes |
|-------|---------|-------|
| Loading / before play | 00:00:00 / 00:00:00 | TimeFormatter returns "00:00:00" for zero ms |
| During playback (controls visible) | HH:MM:SS / HH:MM:SS | Updates via StateFlow combine; invalidate() throttled to 1Hz |
| During playback (controls hidden) | MessageInfo omitted from template | No timeline visible; position still tracked internally |
| Paused | HH:MM:SS / HH:MM:SS | Controls revealed on pause action; position frozen at pause point |
| Seeking | HH:MM:SS / HH:MM:SS | Position updates after seek settles via onPositionDiscontinuity |

### Seek Mechanism (Critical Platform Constraint)

Car App Library 1.7.0 provides no drag-seek / scrub widget in NavigationTemplate. The "progress slider" deliverable from REQUIREMENTS.md and ROADMAP.md is implemented as **step-seek buttons** (±10 seconds) because no interactive Slider API exists in this template type.

The ROADMAP.md risk note ("Car App Library may restrict SeekBar interactivity; fallback to ExoPlayer built-in player UI controls if needed") is resolved: the fallback is step-seek via ActionStrip. ExoPlayer's built-in player UI controls are not compatible with SurfaceContainer rendering in the NAVIGATION category — they would require switching to MEDIA category, which CLAUDE.md explicitly forbids.

This is not a regression — it is the correct implementation for the platform. The UAT criterion "Slider visible and interactive" maps to: seek buttons visible and seek works within ±2 seconds of target.

### Driver Distraction Compliance

| Rule | Implementation |
|------|---------------|
| No touch input while driving | Car App Library Restriction API enforces this automatically — all ActionStrip button OnClickListeners are blocked by the host when the vehicle is moving |
| No complex UI changes while moving | invalidate() / template refresh is allowed while moving; content-change (text update) is host-permitted for NavigationTemplate |
| Parked-only seek | Enforced by host, not by app code |

## Copywriting Contract

Car App library templates do not use standard form copywriting (CTAs, empty states). The following covers the text surfaces Phase 1 owns.

| Element | Copy | Notes |
|---------|------|-------|
| Timeline text | HH:MM:SS / HH:MM:SS | No label prefix; format is self-explanatory on playback screen |
| Zero-duration state | 00:00:00 / 00:00:00 | Shown before ExoPlayer reports duration; acceptable as loading indicator |
| Playback error toast | "Playback error: {message}" | CarToast, LENGTH_LONG; already implemented in VideoPlaybackScreen |
| No-media state | Not applicable | VideoPlaybackScreen is only pushed when a MediaItem is selected; empty state is in BrowseScreen (out of scope for Phase 1) |
| Destructive confirmation | Not applicable | Phase 1 has no destructive actions (stop exits screen; no data is deleted) |
